TikTok tracking for sequencepure.com: the full setup, from the first step

This is everything needed to get TikTok tracking working on the site, in order. Steps 1 and 2 need someone with access to the TikTok account and a phone. Everything after that can be handled for you.

Right now the site has Google Analytics and a Snapchat pixel on it. There is no TikTok pixel of any kind, so TikTok currently cannot see a single visit, add to cart or purchase.

Step 1. Finish the phone verification on the TikTok account TikTok will not open Events Manager until the account has a verified phone number. It sends a code by SMS, so it has to be done by whoever holds that phone.

  1. Sign in at ads.tiktok.com
  2. If a banner says "Verify your phone number for security", click it. If not, open
  3. Settings, then Account settings, and verify the number there.
  4. Enter the code TikTok sends.

If the code does not arrive, the usual causes are a number already attached to another TikTok account, or a carrier blocking the short code. Try a different number on the account, and check that the country dial code is right.

Step 2. Turn off the ad blocker for TikTok Whatever browser is used for this, AdBlock or similar must be paused for ads.tiktok.com. TikTok's own pages will not render properly behind it. It also blocks tracking requests, which later makes a perfectly healthy pixel look broken when it is being tested.

Step 3. Create the pixel 1. In TikTok Ads Manager, open Events Manager, then Web Events. 2. Click Set up Web Events, choose TikTok Pixel, then Manually install pixel code. Do not pick a partner or "Developer Mode" install. The code is going in by hand through the site's snippet plugin, which gives more control than the plugin route. 3. Name it something obvious, for example Sequence Pure - Web. 4. Choose Standard Mode. 5. Copy the Pixel ID. It is a short string of letters and numbers. That ID is the one thing needed to make the browser half work.

Step 4. Create the Events API access token This is the piece that makes server side tracking possible. It cannot be generated from the website end, only from inside TikTok.

  1. Still in Events Manager, open the pixel just created.
  2. Go to Settings, then find Events API.
  3. Click Generate Access Token.
  4. Copy it once and keep it somewhere safe. TikTok will not show it again.

Step 5. The browser half goes in through WPCode The site already has WPCode installed and active, so nothing new needs to be bought or added.

  1. In WordPress, open Code Snippets, then Add Snippet, then Add Your Custom Code.
  2. Name it TikTok Pixel - base.
  3. Set the code type to HTML Snippet.
  4. Paste the pixel base code from TikTok, which already contains the Pixel ID.
  5. Set the location to Site Wide Header.
  6. Save and set it to Active.

Then a second snippet handles the shop events (product views, add to cart, checkout and purchase), so TikTok sees what people actually do rather than only that they arrived.

Step 6. The server half A second snippet sends the same events directly from the site's server to TikTok using the access token from step 4. This matters because browser tracking alone loses a large share of events to ad blockers, iOS privacy settings and people bouncing before the page finishes loading.

The one thing that must not be got wrong: the browser event and the server event for the same action have to carry the same event ID. If they do not, TikTok counts one purchase as two, and the reporting will overstate results while the cost per purchase looks better than it really is.

Step 7. Check it actually works Do not trust a green tick on its own.

  1. In Events Manager open Test Events and follow the on screen instructions.
  2. With the ad blocker off, visit the site, open a product, add it to the cart and begin checkout.
  3. Each event should appear in Test Events within a few seconds, and should show up twice, once
  4. from the browser and once from the server, deduplicated into a single event.
  5. If an event never appears, the usual causes in order are: the ad blocker is still on, the
  6. snippet is saved but not set to Active, or caching is serving an older copy of the page. Clear
  7. the site cache and try again.

What is needed to move Only two values are blocking everything from step 5 onward: the Pixel ID from step 3 and the Events API access token from step 4. Once those exist, the rest is quick.
